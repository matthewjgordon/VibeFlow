# Implementation reports

Record implemented changes, rationale, validation results, limitations, and
effects on durable knowledge. Create the report before implementation so it
can support checkpoints and interrupted runs.

Name it `YYYY-MM-DD <Workstream Name> Report.md` using the creation date.
Resume the existing report for the same workstream; do not create a new daily
report. If multiple reports match, resolve the ambiguity before updating one.

A report should identify source intent, applicable validation, preflight,
per-slice status/results, outcome, implemented and deferred scope,
architectural rationale, changed systems, compatibility/migration concerns,
known limitations, and knowledge reconciliation. Keep technical validation
and human acceptance distinct; label pending human evaluation explicitly.

Link supporting [test evidence](../test-reports/README.md), the source
[workstream](../active-workstreams/README.md), and affected
[wiki pages](../wiki/01%20Home.md). Add actual report links here when created.
No implementation or acceptance is claimed by this starter.

# Test reports

Keep validation results and supporting evidence here. State what was tested,
the relevant source revision/version when available, environment, exact
procedure or command, outcome, and remaining gaps. A report is evidence of
actual execution, not a list of intended tests.

Use descriptive names, with a date when it distinguishes runs. Place relevant
logs or images in clearly named evidence subfolders and link them from the
report. Exclude credentials, personal data, and unnecessary private paths from
shared evidence.

Link the corresponding [implementation report](../implementation-reports/README.md)
and applicable validation contract. Record skipped or unavailable checks with
reasons. Keep technical results separate from human acceptance.

Add actual report links here when evidence exists. No tests have been run by
copying this starter.
